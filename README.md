# 옥키 · 방 알림과 첫 1년

2026.10.25 PC 통합 와이어프레임을 반영한 한국어 반응형 체험 사이트입니다. 기존 디자인과 브라우저에 저장된 신청·상담·커뮤니티 기록을 보존합니다.

## 실행과 검증

`src`는 직접 관리하는 HTML·JavaScript·CSS 원본 폴더이며, 정적 웹 서버의 루트로 제공합니다. 빌드·의존성 설치는 필요하지 않습니다.

GitHub Actions와 동일한 검증은 Node.js 24.18.1에서 다음 순서로 실행합니다. 현재 npm 의존성은 없으며 lockfile을 관리합니다.

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run check
npm run test:ci
npm run build
```

## GitHub Actions → Vercel 배포

대상 저장소: https://github.com/juno-gachon/Okki. 현재 배포 대상은 브라우저 저장소 기반 정적 시제품입니다. 실제 Auth·DB·문자 연동은 포함하지 않습니다.

- `.github/workflows/ci.yml`: PR 및 `main`/`preview` push에서 구문 검사·기존 테스트 4개·빌드 검사를 실행합니다. TypeScript가 없어 타입 검사 명령을 만들지 않습니다.
- `.github/workflows/deploy.yml`: `main` push는 Production, `preview` push는 Preview로 배포합니다. 동일 커밋의 검사·테스트를 통과한 뒤 Vercel CLI 65.11.0으로 `pull` → `build` → `deploy --prebuilt`를 실행합니다. PR에서는 배포 비밀값을 사용하지 않습니다.
- `vercel.json`: Framework `Other`에 해당하는 `null`, 출력 폴더 `src`, 빌드 `npm run build`를 설정합니다. Git 자동 배포를 비활성화해 Actions와의 중복 배포를 방지합니다. Vercel Root Directory는 저장소 루트로 지정합니다.

최초 연결 절차:

1. Vercel에 대상 프로젝트를 생성하거나 기존 프로젝트를 지정합니다. Preview/Production 프로젝트·환경값을 분리합니다.
2. GitHub 저장소 Settings → Environments에 `preview`, `production`을 생성합니다. 배포 허용 브랜치를 각각 `preview`, `main`으로 제한하고, `production`에는 검토자를 설정합니다. `main` 브랜치 보호에서 `CI / check`를 필수 검사로 지정합니다.
3. 각 Environment의 **Secret**에 `VERCEL_TOKEN`, **Variables**에 해당 프로젝트의 `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`를 등록합니다. 토큰은 채팅·코드에 적지 않습니다. CLI 버전은 workflow에 고정되어 있습니다.
4. `preview` 브랜치로 push하여 Actions 실행과 배포 URL을 확인합니다. 페이지 및 JavaScript·CSS 로딩을 확인한 뒤 PR로 `main`에 반영합니다. 실행 요약에 커밋 SHA와 배포 URL이 기록됩니다.

현재는 로컬 설정 및 검증까지 완료했으며, GitHub Actions 실행·Vercel 빌드·실제 배포는 아직 확인하지 않았습니다. 업무 DB migration과 실제 문자 발송은 앱 배포와 별도 작업입니다.

공식 참고: [GitHub Actions와 Vercel](https://vercel.com/kb/guide/how-can-i-use-github-actions-with-vercel), [Vercel 정적 설정](https://vercel.com/docs/project-configuration/vercel-json).

## 주요 흐름

- 랜딩: 조건 등록 → 정보 확인 → 방 알림 → 상담·방문 연결. 최신 일상은 왼쪽, 최신 새로 왔어요는 오른쪽에 표시합니다.
- `#/wait`: 2단계 일정·지역·예산·생활 조건·연락처·개별 동의. 미정 비용과 0원을 구분하고 지도 왕복 시 초안을 보존합니다. 체험 연락처 확인에는 화면에 보이는 일회용 번호를 사용하며 실제 SMS·이메일은 보내지 않습니다.
- `#/activity`: 방 알림 / 공간 상담 / 내 방 등록. 등록 후 자동 매칭 결과 없이 대기합니다. 조건 변경, 일시 중단·재개, 집 구함, 등록 삭제, 급한 상황 도움 요청, 알림 동의 설정을 제공합니다.
- `#/alert/<알림ID>`: 공간 상세 상단, 상담 form 하단. 조건 충족·불일치·미확인을 구분하며 기존 등록 내용을 가져옵니다. 제출은 별도 상담으로 저장하고 원본 조건을 유지합니다. 완료 팝업의 닫기·확인 모두 내 활동의 상담 탭으로 이동합니다.
- `#/consultation-detail/<상담ID>`: 제출 당시 공간·조건 사본, 작성 내용, 진행 기록, 추가 문의, 취소. 방 알림 상태와 상담 취소는 독립적입니다. 같은 공간의 진행 중 상담을 중복 제출하지 않습니다.
- `#/provide/tenant`, `#/provide/owner`: 세입자와 소유자·담당자 양식 분리. 비공개 주소, 퇴거일과 실제 입주일 구분, 전달 범위·권한 확인, 사진, 수정 요청·철회 이력.
- `#/tasks`: 첫 1년 할 일 선택·진행 상태·개인 메모. 확인된 공식 공고가 없으므로 정책 금액·대상·기간을 단정하지 않고 신청 링크를 비활성화합니다.
- `#/community/daily`, `welcome`, `info`, `policy`: 4개 탭, 사진 순서 변경·삭제·미리보기, 글·댓글·공감·저장·신고. 댓글·공감으로 최신 게시 순서를 바꾸지 않습니다. 랜딩 링크는 게시글의 실제 탭과 해당 글로 이동합니다.
- `#/area`: 보조 생활권 도식. 지역·시설 검색, 외부 지도 링크, 선택 지역의 등록 조건 반영. 방 핀과 제보 주소는 표시하지 않습니다.
- `#/admin`: 일반 메뉴에 없는 로컬 운영 시뮬레이션. 제보자 연락 범위, 임대 의사, 안내 권한, 실제 조건을 모두 검토하고 확인 주체·날짜·근거를 기록해야 안내할 수 있습니다. 불일치는 발송 차단, 미확인은 별도 확인 안내. 변경·마감·읽음·상담·건너뜀 기록을 제공합니다.

## 통합본 반영

- `#/provide`: 공인중개사 매물과 현재 거주자 공동거주 모집으로 구분합니다. 사무소 정보와 개별 매물 확인은 별도이고, 거주자 모집은 현재 거주·동의·모집 인원·잠자리·분담금·생활 규칙을 받습니다. 공동거주를 원하지 않는 방 알림 조건에는 거주자 모집을 안내하지 않습니다. 예전 세입자·소유자 기록도 유지합니다.
- 모든 본문 양식의 하단에 임시 저장을 제공합니다. 사진·선택한 지역·다중 선택을 복원하고, 공간별·질문별 초안을 분리합니다. 일회용 확인 코드는 복원하지 않습니다.
- `#/community/info`, `#/questions`, `#/reviews`: 옥천 전체 / 읍면 / 리 단위 게시 범위를 공유합니다. 사용자가 상위 범위를 선택할 때만 목록을 바꾸며 기존 글의 범위는 바꾸지 않습니다. 실제 읍면과 옥천읍 법정리 목록을 제공합니다. 다른 읍면은 현재 읍면 단위까지 지원합니다. 리 명칭 출처: https://oc.go.kr/www/contents.do?key=658
- `#/ask`, `#/question/<id>`: 사진 없는 질문, 선택한 동네와 참여 관계, 비슷한 질문, 답변 근거·경험 시기·이해관계, 도움 표시·해결·운영 도움 요청을 연결합니다. 새 답변 수신을 선택한 질문만 알림함에 반영하며 해당 답변으로 바로 이동합니다.
- `#/review-write`: 현재 거주·과거 거주·방문 경험과 주제별 후기, 통근·비용·이해관계를 구분합니다. 직접 입력만으로 인증 배지를 만들지 않습니다.
- 공간 상담 상세에 생활권 질문·후기·저장·비교를 연결합니다. 비공개 주소·연락처는 질문에 복사하지 않습니다. `#/saved`에서는 실제 안내된 공간을 비교하고 장소·질문·후기·선택한 할 일을 다시 봅니다. 저장과 변경 알림은 별개입니다.
- `#/settle`, `#/life`: 계약 예정·입주 전·입주 완료 상태를 직접 입력하고, 방 알림 종료·일시 중단·계속 받기를 선택합니다. 상담 취소는 독립적입니다. 할 일·지도·질문 답변·내 경험과 저장한 정보를 연결합니다.
- `#/notifications`: 방 소식, 질문 답변, 내가 정한 할 일 날짜와 신고 처리 기록을 모읍니다. 외부 발송은 하지 않으며 준비 날짜 알림은 알림함을 열 때 확인합니다. 알림 종류·개별 동의·방해 금지 시간·요약 설정을 보관합니다.
- `#/area`: 실제 지도 API 대신 명확히 표시한 시설 도식과 외부 카카오맵 검색을 제공합니다. 실제 확인되지 않은 주소·운영시간·출처·확인일은 미확인으로 표시합니다.
- `#/report/<kind>/<id>`, `#/reports`: 정보 정정·신고·차단·처리 이력·재검토 요청. `#/verification`은 확인 방법 안내 요청이며 실제 배지는 부여하지 않습니다. `#/community-admin`은 일반 메뉴에 없는 로컬 운영 체험입니다.

## 체험 범위

모든 입력과 기록은 현재 브라우저 localStorage에만 보관됩니다. 다른 사람·기기에 공유되지 않고 운영팀에도 전송되지 않습니다. 실제 인증, 로그인·운영자 권한, 데이터베이스, 지도 API, 문자·이메일 발송, 외부 중개사 연결은 구현되지 않았습니다. 운영자 체험 URL은 보안 경계가 아닙니다. 인증 증빙 원본은 수집하지 않습니다. 기존 신청·상담·커뮤니티 데이터 키를 유지합니다.

## 검증 범위

기존 회귀 테스트는 랜딩 커뮤니티 이동·최신순 유지, 방 알림 등록과 연락처 체험 확인, 상담 자동 채움과 원본 보존, 중복 차단, 완료 팝업 이동, 알림/상담 상태 분리, 저장 실패, 운영 확인 제한을 검사합니다.

통합 테스트는 지역별 글 격리, 사진 없는 질문, 저장과 알림 동의 분리, 답변 링크, 실패한 저장의 상태 유지, 공개 입력 이스케이프, 자기입력과 인증 구분, 등록 유형 확인, 공동거주 조건 차단, 초안 분리, 저장한 할 일, 입주 상태와 상담의 독립성, 각 화면 템플릿, HTTP 미리보기 ID 생성을 검사합니다.

관리형 브라우저 미리보기에서 랜딩 화면, 지역 선택 → 질문 작성, 임시 저장 → 새로고침 복원, 질문·답변 제출 → 알림함 → 해당 답변 이동, 방 등록 유형 선택 화면을 직접 점검했습니다. 실제 외부 서비스 발송·인증·지도 연동은 검증 대상이 아닙니다.

## 코드 구조 정리 (주석 포함 버전)

- `src/router.js`: URL 해석, 화면 선택, 화면별 이벤트 연결과 공통 후처리. 새로운 경로는 이 파일에서 관리합니다. `index.html`에서 기능 파일 다음에 불러와야 합니다.
- `src/flow.js`: 방 알림과 대기 흐름, 현재 랜딩페이지 등. 랜딩페이지 문구와 섹션은 이 파일의 `home()`에서 수정합니다.
- `src/app.js`: 저장소와 공통 UI 등 기본 기능. 이후 파일에서 완전히 대체되던 중복 기본 함수는 제거했습니다.
- `src/integrated.js`, `src/neighborhood-map.js`, `src/public-housing.js`, `src/vacancy.js`: 각 기능의 화면, 데이터 및 이벤트.

기존 코드와의 호환을 위해 일부 화면 구성 함수는 여전히 다른 파일의 함수를 확장합니다. 특히 등록, 생활 지도, 상담 및 관리자 화면의 단계적 통합은 추가로 필요합니다. 스크립트 순서를 임의로 바꾸지 마세요.

검증: `node tests/wait-flow.test.cjs`, `node tests/integrated-flow.test.cjs`, `node tests/public-housing-flow.test.cjs`.
이 코드는 브라우저 저장소 기반 시제품이며 서버나 실제 회원 인증 기능을 포함하지 않습니다.
